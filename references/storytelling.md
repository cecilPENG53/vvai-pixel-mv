# 讲故事的方法（故事线 → 分镜表 → 出片）

第 2 集《坏女孩》第一版只按关键词换场，用户的反馈是：

- 没有故事、不连贯；
- 角色只会在桌面上跳；
- 歌词出现得太平，转场不够狠。

故事版改成了下面这套顺序，以后每首歌都这样做。完整例子：`assets/examples/bad-girl.故事线.md` 和 `bad-girl.story.json`。

## 1. 先问故事，再写故事线

- 用户给了故事（“主角不珍惜，分手后才觉悟，她已经和别人在一起”），就照着写。
- 没给，就根据歌词提 2–3 个一句话故事让用户挑。
- `MV story <工程>` 生成 `故事线.md` 模板，逐句表的句号和时间已经填好。按顺序填：
  1. **一句话故事**：谁、对谁、做了什么、结局怎样。
  2. **角色**：通常 2–3 个。每个角色一个外形（kind）和一个贯穿全片的标志，比如墨镜、蝴蝶结。
  3. **母题**：2–3 个贯穿道具或地点，开头埋、结尾收，比如牵着的手、围巾、站台。
  4. **分幕**：4–5 幕，每幕一种情绪、一个主场景。高潮幕给最长的时间。
  5. **逐句**：每句写清在哪、谁在场、发生什么、歌词怎么出现、怎么转进来。
- 故事线给用户确认后再写 story.json。

## 2. 每句都要有事发生

- **每句歌词至少一个剧情动作或一种歌词互动**。不能整段都只是卡拍跳。
- **剧情动作落在歌词的关键字上**：用 `cues.json` 里该字的时间，不要落在句首。例如“放开”的“放”字松手，“转身”的“转”字转身。
- **歌词跟着剧情走**：
  - 哭的句子用 `drip`；
  - 雨里消失用 `wash`；
  - 被哼一口气用 `blown`，`out` 对准 puff 的时间；
  - 对屏幕说的话用 `type`，对人说的用 `say`，想起来的用 `memory`；
  - 心碎那句用 `behind` 加 `shatter`。
- **同一种歌词方式不连用超过 3 句**。全片至少用 5 种进场或退场。

## 3. 转场是剧情的一部分

- 每次换场都有理由：
  - 列车开过 → 人没了（`train`）；
  - 钻进手机 → 看到通话记录（`zoom`）；
  - 一幕结束 → 圆圈收拢（`iris`）。
- 全片至少用 4 种转场，同一种不连用。
- 高潮幕可以是一个长段（20 秒以上），靠 `camKeys` 推拉、角色走位、灯光变化撑住，不必频繁换场。

## 4. 电脑桌面是“观众视角”

- 觉悟、回看、对比类的段落用桌面段：观众看到整块电脑桌面，场景在窗口里演。
- 常用手法：
  - 两个窗口并排对比，比如“她 · 现在”和“我 · 现在”；
  - 不想看的窗口收进 Dock，留下的窗口放大；
  - 歌词写在窗口玻璃上（`glass`）；
  - 最后开一个回忆窗口，回到开头的地点，让母题收尾。

## 5. 分镜表给用户看，改到满意再出片

1. 运行 `MV board <工程> --frames`：每段截 1–3 张画面，写进 `分镜表.md`。表里只有句号，没有歌词正文。
2. 把分镜表发给用户（SendUserFile），说明可以改哪些：场景、动作、转场、歌词方式、时间。
3. 用户提修改 → 改 story.json → 再运行 `board`，版本号自动加 1，旧版的 story.json 存在 `分镜/历史/`。
4. 这一步可以来回很多次。用户想先看动起来的效果时，可以对某一段截更多帧给他看，但不渲染整片。
5. 用户明确说“可以出片”“就这样渲染”，才运行 `MV approve <工程>`，然后 `MV render`。
   - “好的”“看着办”这类含糊的话不算确认，要再问一句。
   - `render` 会核对 story.json 的指纹：确认之后又改过，就拒绝渲染，要重新出分镜表、重新确认。
   - `render --force` 只在用户明说“不用看分镜，直接出”时用。

## 自查清单（出分镜表之前）

1. 一句话故事能不能从画面里看出来？把歌词遮住，只看分镜画面，能不能讲出前因后果？
2. 每个角色都有出场和退场吗？母题首尾都呼应了吗？
3. 有没有哪一句什么都没发生？
4. 转场有没有 4 种以上？受惊反应包是不是不超过 2 次，并且落在真正的反转上？
5. 全屏闪白每秒有没有超过 3 次？
